## Overall assessment

**Solid**
- The core is well built. The FAT12 reader keeps every slice in bounds.
- Saves are replaced atomically, with tests that inject a fault at each step.
- The content decoders are bounds-checked and free of leaks. A mutation fuzz of films, sprites,
  rooms, object art, messages and icons, run in Debug with the leak checker, found no panic and
  no leak.
- There is no shared state with an audio thread: SDL's queue API is used, with no callback.
- The behaviour engine follows the evaluation order in DESIGN.md section 4. A scratch test
  checked rules 1 to 5.
- Random input on all seven levels for 6,000 frames each, stalls included, never panics.
- Nothing uses much CPU. The engine takes under 0.2% of the time, and the densest music cue 0.47%
  of real time in ReleaseFast.

**Weakest**
- **Failure policy.** Any error from `Game.update` ends the program (`src/sdl/host.zig:155`),
  while much content is only checked when it is first used. Two consequences can be reproduced:
  using a city map terminal ends the game, and an audio device that grants another format ends it.
- **Input state.** Several screens bypass the key tracker, which loses key releases.
- **Rules against the code.** The engine models the original's memory layout in several places,
  although AGENTS.md and DESIGN.md forbid it.
- **Leftovers from the template.** Without disks the program still starts the template's
  placeholder game, and several documents describe it as if it were Flashback.

Status labels used below: **confirmed** means reproduced or proven from the code; **suspected**
means plausible but not reproduced. Scratch evidence is under `/tmp/flashback/review/`
(`lead/`, `hosts/`, `audio/`, `behavior/`, `scenes/`, `content/`).

## 1. Bugs

### B1. Using any of the city's four map terminals ends the game. Severity: high. Confirmed.
- **Where:** `src/shared/content/vector_cinematic.zig:430-445`, reached through
  `scenes/story.zig:25`, `game.zig:534` and `sdl/host.zig:155`.
- **Statement:** the page-loop importer rejects one page shape: a release loop whose
  destination is negative (it ends the film) while its idle target lies ahead of the command.
  Entries 0 to 3 of the city's map film (scenes 26 to 29) all have that shape and fail with
  `error.UnsupportedCinematicInteraction`. The error goes up through `Game.update`, and the host
  exits with "game update failed".
- **Evidence:**
  - The extracted city data has four interactive placements on `behavior_132`, in rooms 0, 13,
    38 and 51. That behaviour plays scenes 26 to 29 when it receives `operate`.
  - With only Conrad's start position changed in the data set (room 0, x 112 or 120), the run
    `flashbackz-agent --data lead/dm --scene city --key 5:backspace --key-down 150:left_shift
    --key-up 200:left_shift disk1.img disk2.img` exits 1 with `error: UnsupportedCinematicInteraction`
    at `vector_cinematic.zig:445`. At x 96 and 104 (not touching the terminal), the run goes on
    normally. Scene 25, entry 4 of the same film, imports and plays.
  - PLAN.md ticks "interactive film pages; mission terminals" (PLAN.md:101), and item 03 claims
    every room of every level was compared. Neither covered using these terminals.
- **Direction:**
  - Support this shape, with a positive unit test for each page-loop shape. Today no test covers
    any interactive page.
  - Import every film named in `scenes.zon` once at load, so an unsupported film shows up at
    startup, not in play.
  - Consider making a film that fails to import non-fatal: skip it and log it.

### B2. An audio device that grants a format other than the one requested ends the game (or overruns a buffer). Severity: high on Windows. Confirmed from code and SDL source; not run on Windows.
- **Where:** `src/sdl/backend.zig:798`, and the consumers `scenes/story.zig:56`,
  `scenes/ending.zig:336`, `scenes/front_end.zig:132`, `audio/effects.zig:111`,
  `audio/megadrive_tunes.zig:139` and `audio/megadrive/synth.zig:77`.
- **Statement:** the device is opened with
  `SDL_AUDIO_ALLOW_FREQUENCY_CHANGE | SDL_AUDIO_ALLOW_CHANNELS_CHANGE`, so SDL may return a
  different channel count or rate. Each consumer then treats anything but its own expectation as
  fatal:
  - The films and the ending need exactly 2 channels at 44,100 Hz.
  - The title music and the effects need 2 channels.
  - The Mega Drive synth asserts a rate of at most 53,267 Hz.
- **Evidence:**
  - In the Windows build's SDL 2.32.10, WASAPI sets `spec.channels` to the mix format's
    (`SDL_wasapi.c:441`), and `SDL_audio.c:1460` reports it because channel changes are allowed.
    The rate is kept, since WASAPI's own resampler is used (`SDL_wasapi.c` `#if 0` branch).
  - A Windows PC whose default output is 5.1, 7.1 or a mono headset therefore gets 6, 8 or 1
    channels. The branding music at startup then returns `UnsupportedAudioFormat`, and the game
    quits before the title.
  - On Linux, SDL's ALSA `hw:` and JACK backends can change the rate. The title music adapts,
    but the first film with music ends the game.
  - With `--megadrive` and a rate above 53,267 Hz, a scratch test hits the synth's assertion in
    Debug. In ReleaseFast, writes run past the 900-frame `frames` buffer.
  - The agent backend always grants the format it is asked for, so no test reaches this path.
- **Direction:** stop allowing format changes, so SDL converts. Or open the device once, in one
  place, and resample or downmix there (see D2).

### B3. A key released while the options dialog or the inventory is open is ignored when pressed again. Severity: medium. Confirmed.
- **Where:** `src/shared/scenes/level.zig:373` (`pollOptions`), `:609` (`pollInventory`),
  `:772` (`Keys.release`) and `:517-522` (`finishFilm`).
- **Statement:** these modal loops pass `key_up` and `focus_lost` to `Keys.controller`, which
  drops them. So `Keys.down` keeps the bit. On resume, `release()` copies it into `ignored`, and
  the next fresh press of that key sets no `held` bit. Only a key-repeat event clears it.
- **Evidence:** jungle, film skipped, Right held, then Escape, Right released inside the
  dialog, resume, then Right held from frame 90 to frame 170.
  - Conrad stays at x=48.
  - With one `--key-repeat 110:right`, he reaches x=72.
  - Without the dialog he reaches x=97.
  - A short tap of a released key is lost entirely.
- **Related, same root cause:**
  - Keys pressed during a film are queued and applied after `finishFilm` has already called
    `release()`, so they act at once. This contradicts the comment at `level.zig:515-516`.
  - In the inventory, gamepad events go to the gameplay keys, but the menu reads only
    `inventory.keys`. A gamepad can open the inventory but cannot move in it or close it, and
    Backspace opens it but does not close it.
- **Direction:** one key tracker fed by every event, whatever screen is open. Modal screens
  read presses from it (see D3).

### B4. Missing or partial game files start the template's placeholder game instead of failing. Severity: medium. Confirmed.
- **Where:** `src/sdl/host.zig:22` (`assets_required = false`), `src/shared/game.zig:285` and
  `src/native/bundle_check.zig`.
- **Statement:** with no disks, only one disk, or a directory without the menu art, the game
  silently runs the template's bouncing-ball smoke scene. The window title is
  "flashbackz — platform smoke".
- **Evidence:**
  - `flashbackz-agent --frames 2 disk2.img` prints `info: data set not extracted: NotFound`,
    then `{"scene":"smoke"}`, and exits 0. The same happens with no arguments.
  - A standalone build made with only `-Ddisk2`, or only `-Dmegadrive`, runs the placeholder.
    With `-Dmegadrive` only, the built-in cartridge is also ignored ("assets: none").
  - `bundle_check` checks each file on its own, never that both disks are present.
- **Direction:**
  - Require the assets (`assets_required = true`) and report which disk is missing.
  - Make `build.zig` require both `-Ddisk1` and `-Ddisk2` before it builds a standalone build.
  - Move the placeholder out of `Game` (D4).

### B5. A catch-up frame drops the first walk's world message and its zoom hits. Severity: medium if the original keeps them. Mechanism confirmed; fidelity not checked.
- **Where:** `src/shared/behavior/world.zig:377` (`self.requests = .{}` on every walk), with
  `scenes/level.zig:478-489` and `:533-545`.
- **Statement:** `walk()` latches `requests.scene` from a `.first_of_two` walk, but it does not
  draw that walk. The `.catch_up` walk then resets `world_message` and `hits` before the frame's
  only draw.
- **Evidence:** the scratch test `behavior/t/twowalks.zig` sets `show_message` in the first
  walk; the message is null after the catch-up walk. Sounds survive, because they are submitted
  per walk; messages and hits do not.
- **Direction:** reset requests once per frame, or latch the message and the hits as the scene
  is latched. Record whichever behaviour the original has.

### B6. Escape in a level reacts to auto-repeat, and a quick tap is lost. Severity: low to medium. Confirmed.
- **Where:** `src/shared/scenes/level.zig:791-793` (`self.escape = down` for every key-down,
  repeats included).
- **Evidence:**
  - Holding Escape to skip the level's opening film opens the options dialog once repeats arrive.
    Up then Enter then abandons the game. The title screen guards against exactly this
    (`front_end.zig:293`; PLAN.md:250-256 records that guard for the title only).
  - A press and release within one 28.6 ms frame clears the flag before it is read, so the
    agent's `--key F:escape` can never open the options.
- **Direction:** latch Escape on a fresh press, as the title does.

### B7. The data-set loader accepts data the engine cannot run, so DESIGN.md 3's "fails loudly" does not hold. Severity: medium, because DESIGN 7 promises extension through data. Confirmed with edited data sets.
- **Where:** `src/shared/behavior/data_set.zig:647-728`, `operations/carriers.zig:326`,
  `world.zig:199`.
- **Evidence:**
  - **More than 256 characters:** `Checkpoint` holds `[256]Character`, and the loader never
    checks the count. The first `checkpoint` effect then trips `std.debug.assert` in Debug, or
    slices out of bounds in ReleaseFast. The city already has exactly 256 characters, so adding
    one placement (the extension DESIGN 7 describes) breaks it (`behavior/t/cp.zig`). The literal
    256 also appears in `game.zig:231`, `contacts.zig:12` and `perception.zig:491,524`.
  - **Unknown or misspelled character fields** are silently ignored, and non-bool flags read as
    false. With `.activ = true`, Conrad stays asleep (`behavior/v_typo`). `parseRule` rejects
    unknown fields; `parseCharacter` does not.
  - **Zero characters** gives an index-out-of-bounds at `scenes/level.zig:209`. Nothing checks
    that character 0 is the player, although about 17 sites assume it.
  - **Animation ids** are not checked at load. They fail in play as a bare `MissingAnimation`.
  - **i16 arguments** are accepted whole, but the arithmetic does not wrap. For example,
    `.wall_ahead = -32768` overflows at `terrain.zig:11`, `.chance = -1` overflows at
    `timers.zig:177`, and a range of 32767 overflows in `perception.zig:96,202`.
  - **A footprint wider than 16 cells** in a room that is its own neighbour loops forever in
    `contact.zig:229-247` (`behavior/t/loop.zig`).
  - **`scenes.zon` and message text:** an empty credit text panics at `ending.zig:424`. If no
    ending film resolves, `films[0]` is read uninitialised (`ending.zig:102`). A byte outside the
    font becomes `MissingGlyph` in the middle of play.
- **Direction:** validate when loading, with the existing diagnostic:
  - unknown fields, the character count, player index 0, animation ids and argument ranges;
  - the footprint width, at most 16;
  - film resolution and glyph coverage.

### B8. The agent without `--saves` uses, and creates, the user's real save directory. Severity: low. Confirmed.
- **Where:** `src/agent/main.zig:134` and `native/cli.zig:291-295`.
- **Statement:** with disk paths but no `--saves`, `providers.open` uses
  `$XDG_DATA_HOME/flashbackz/saves` and reads its VOLUME record.
- **Evidence:** two identical runs, with a VOLUME record written between them, gave different
  `--pcm` output. This contradicts `main.zig:6-7` ("Without them, it runs on in-memory
  providers, so the run touches no file") and the determinism claim at `main.zig:3-4`.
- **Direction:** use in-memory storage in the agent unless `--saves` is given.

### B9. Command-line options that are silently ignored, and standalone `--extract`. Severity: low. Confirmed.
- **Silently ignored** (`native/cli.zig:296`): `--megadrive` and `--data` without disks, and a
  built-in cartridge without built-in disks. `--megadrive /nonexistent.md --data /nonexistent`
  exits 0 in the smoke scene.
- **Standalone `--extract`** (`cli.zig:95`, `cli.zig:149`) ignores the built-in disks and
  demands ASSET_PATH. That contradicts DESIGN 3: the standalone build "reads them as it would
  read the same files given there".
- **Empty subject:** `--extract` into an unwritable directory, or with an unreadable `--names`,
  prints "cannot open the : permission denied". `cli.zig:115-124` sends any error of the open
  set to `writeFailure` after `openAssets` has reset `failed`.
- **Direction:** reject these options without disks, read the built-in disks for `--extract`,
  and give the output and names failures their own subject.

### B10. Sprite decode errors are swallowed. Severity: low to medium. Confirmed.
- **Where:** `src/shared/content/character_art.zig:57` (`catch continue`) and `:75-79`.
- **Statement:** every error other than out-of-memory becomes `art.missing += 1`. Nothing ever
  reads `missing`.
- **Evidence:**
  - `PERSO.SPR` truncated to 5,000 bytes loads "successfully" with 1,758 sprites missing, and
    Conrad is invisible.
  - On the real disks, the tower silently drops 48 composed sprites (`MissingArtBank`). Whether
    any of them is ever shown was not checked.
  - The field's doc says "no file holds", which is not the only cause.
- **Direction:** tolerate only expected absences, fail on corrupt data, and log the count.

### B11. The continue screen ends the game when 128 key events are queued. Severity: low. Confirmed.
- **Where:** `src/shared/scenes/continue_game.zig:48`.
- **Evidence:** 65 taps injected on one frame of the continue screen make the agent exit with
  `error: InputQueueFull`. In real play it would take a burst of events after a stall. The
  level's queue has no cap at all.
- **Direction:** drop or coalesce events instead of failing.

### B12. The Mega Drive cartridge reader is not overflow-safe, and its checksum check can be bypassed. Severity: low. Confirmed.
- **Where:** `src/shared/content/megadrive.zig:54-88` and `game.zig:306-315`.
- **Statement:** a `MEGADRIVE.MD` placed in an extracted-directory ASSET_PATH reaches
  `Tunes.read` without the SHA-256 check, which only the `--megadrive` path applies. In
  `Tunes.read`, `base + 60`, `base + 4*k` and `at + 35` are u32 sums that can overflow.
- **Evidence:** 2 MiB of 0xFF in that directory gives "panic: integer overflow" at
  `megadrive.zig:68`. `row_count == 0` is also accepted, and `Player.frame` would then index
  `rows[0]`. The doc comment says "Every table is bounds-checked".
- **Direction:** check `isCartridge` in `loadTunes`, and widen the arithmetic to usize.

### B13. The extractor's robustness. Severity: low, but extraction runs in memory at every launch, so these are UB in ReleaseFast on an unexpected edition. Confirmed with synthetic input.
- `src/extract/level.zig:68` via `:574`: a placement whose start state no rule uses reaches
  `unreachable`. The comment "every target and start state is collected" is false: only rule
  source and target states are collected.
- `src/extract/level.zig:289`: `argument + extra` overflows i16 for an argument of 32767.
- `src/extract/root.zig` (`writeEnding`): `stream[at + 1]` and `stream[at + 2]` are read
  without a length check on a truncated credits stream.
- `src/shared/content/level_pack.zig:142`: a 1-byte `GLOBAL.ICN` gives an index out of bounds.
- `src/native/data_set.zig:41`: at startup the extraction report is discarded (`_ =`), so the
  `unknown_N` and `*_raw` operations of another edition are never shown.
- Direction: return errors that name the level and the placement, and log the report's warnings
  at startup.

### B14. Smaller confirmed defects
- **The opening film plays again on Retry.** Continue then Retry with no checkpoint reloads the
  level, and its opening film plays again (`game.zig:485`, `level.zig:241`). The commit claim
  "each film plays once" (d25ed27, a9b6b26) does not cover this path. Whether the original
  replays it is unknown.
- **`Game.stateHash` has no ending case** (`game.zig:344-349`). During the ending it returns the
  placeholder ball's constant hash.
- **A large `--stall` overflows:** `--stall 1:99999999999999` panics in `parseStall`
  (`agent/main.zig:238`), and `1:999999999999` panics in `agent/backend.zig:102`.
- **A closed stderr ends the game:** with `2>&-`, `try err.print` exits 1 before the window
  opens (`sdl/host.zig:95` and later lines).
- **Lost events:** `sdl/backend.zig:590` drops an event on out-of-memory
  (`append(...) catch {}`). A lost key-up leaves the key stuck.
- **`content/music.zig:202-203`:** `-profile.limit + 2` overflows i32 for limits near the type's
  bounds. `Profile.parse` rejects only minInt. This needs a corrupt PRF file.
- **Two bank decoders disagree on raw banks** (`art_bank.zig:20-30` against
  `floppy_rooms.zig:86-94`): one reads a negative count, the other a flag bit and a 15-bit count.
  This is latent, since no bank file on these disks has a raw bank. Suspected.
- **Stale-awake letters (suspected).** Letters sent to awake but inactive characters are never
  freed (`world.zig:806-828`). Each holds one of the 256 pool slots until a continue.
  Reachability with real data was not checked.

## 2. Design

### D1. The engine models the original's memory layout, against AGENTS.md, DESIGN 2 and 3 and PLAN item 00. Confirmed.
- **Where it happens:**
  - `grid.zig:117-128,200-203` and `carriers.zig:317-320`: the grid as the original's contiguous
    memory, with its data-segment address.
  - `world.zig:776-792`: `outsideByte` switches on three data-segment addresses.
  - `perception.zig:452-559`: the leftward sight scan rebuilds 32-byte placement records, the
    wake list, the live-record base and the mailbox layout.
  - `carriers.zig:89-91`: placements 120 and 248 cannot be boarded, because the original tests
    the low byte of a record address.
- **Supporting fields:** `unknown_byte_29`, `other_flags` and `label_number` exist in the data
  set only to feed these.
- **Why it matters:** besides the rule conflict, it breaks DESIGN 7's locality. Inserting a
  placement changes which characters fall under the 120/248 rule and what the sight scan reads.
- **Direction:** either record an explicit, user-approved exception and confine these quirks to
  one named "original memory" module, or restate each one as a named game rule. Update PLAN 00
  and DESIGN either way.

### D2. One audio device, five owners, no mixer. Confirmed.
- **Owners:** `front_end.music_rate`, `story.audio_open`, `ending.audio_open`,
  `effects.opened` and the placeholder's `game.audio` each open, close and track the device with
  their own flag.
- **Inconsistencies:**
  - They apply three different format policies (B2).
  - `audioOpen` silently closes the previous device (`backend.zig:780`), and the platform contract
    (`platform.zig:283`) does not say so.
  - The pump loop exists twice (`soundtrack.zig:30-52`, `effects.zig:123-144`).
- **Against DESIGN 6:** DESIGN 6 says "AdLib output and game PCM are mixed on a sample clock".
  No such mixer exists: sources take turns on the device, and only the Mega Drive tunes are mixed
  with the effects.
- **Controls:** the tunes are music, but the sound-effects switch (S, and the options row)
  controls them, not the music volume. This needs a user decision.
- **Direction:** one audio output owned by `Game`, opened once, which resamples and mixes the
  sources at the device's format.

### D3. Input state is updated in one path only, and settings have many hand-synchronised copies. Confirmed.
- **Input:** the physical key state changes only in `takeKeys` (`level.zig:649`). The options
  dialog, the inventory and the films route events elsewhere: this is the root cause of B3 and
  part of B6.
- **Settings:** `Game.preferences`, `level.settings`, `options.menu.settings`,
  `suspended_level.settings`, `story.joystick` and the `front.*` fields hold copies, and zoom is
  kept in both `settings.zoom` and `screen.zoom`. `setJoystick` writes five places
  (`game.zig:420-424, 541-550, 738-755`).
- **`Game.inherited`** is shared by demos, abandoned games and new games
  (`game.zig:441,465,614`). The comment at `level.zig:114` says "none in a new game".
- **Direction:** one key tracker, and one settings owner read where the settings are used.

### D4. The template's placeholder and unused template code are still in the product. Confirmed.
- **In `Game`:** `game.zig:36-188, 757-795, 856-895` hold the bouncing ball, the click, the
  F2/F3 `GPST` save and `TITLE.TXT`. The page buffers are sized for its 320×200 page, and the
  bare `57344` appears 8 times. `State.seed` is documented as "The one random generator of the
  game"; it is not, since the game uses `world.random`.
- **Build steps:** the `smoke` step (`build.zig:184-189`) only exercises this placeholder.
- **Unused code, about 300 lines:**
  - in `sdl/backend.zig`, mouse capture and relative mode, the Ctrl+F10 chord,
    `setMouseScale`/`mouseScaleText` (there is no `--mouse-scale`) and text-input splitting;
  - `Storage.listSaves` and `deleteSave`;
  - `input_recording.Playback`;
  - `settings.zig`, whose `Difficulty` duplicates `behavior/data_set.zig:9`.
- **About 800 lines of vendored chip code that flashbackz never calls:**
  - the PSG and the DAC;
  - `Synth.startSample`, `stopSample`, `holdZ80`, `writePsg` and `advance`;
  - `Resampler.setRate`;
  - the OPL3 four-operator and timer paths.

  Their comments refer to files of sorz and vpoolz that are not here.
- **Direction:** move the placeholder into a test host and fail without disks. Delete the dead
  template code. Mark the chip files as vendored, or trim them, and say which in DESIGN.

### D5. Module boundaries leak in both directions. Confirmed.
- **The engine reads an original format:** `behavior/animations.zig` parses the original
  animation file at run time (header, 4-byte frames, the mirror bit). Per-frame movement, sound
  and pose are not in the data set. This contradicts `content/root.zig:1` ("file layouts stop at
  this boundary") and DESIGN 3 (timings go through the extractor).
- **Extractor-only parsers live in `src/shared`:** `content/placement.zig`,
  `content/rule_table.zig` and `content/string_table.zig` are used only by `src/extract`.
- **Content imports upward:** `content/` imports the engine (`level_pack.zig:17`,
  `character_art.zig:11`) and the scenes (`inventory_artwork.zig:6`, `menu_artwork.zig:7`).
  `content/music.zig` imports `audio/score.zig`.
- **Scenes reach into the World:** the scenes and `Game` write `World` internals directly
  (`score`, `entry_score`, `random`, `shake`, `view_dirty`; `game.zig:496-498,589-592`,
  `level.zig:159,520`).
- **Direction:**
  - Move the animation reader into `content/`, or extract the frames, and update DESIGN.
  - Move the extractor-only parsers into `src/extract`.
  - Move the `artwork()` adapters into the scenes.
  - Give `World` a small hand-off API for the scenes.

### D6. Every runtime error is fatal, and validation is deferred to first use. Confirmed.
- **Where:** `src/sdl/host.zig:155` exits on any error of `Game.update`.
- **Examples:** a film that fails to import (B1), an unexpected audio format (B2), an input queue
  overflow (B11), a missing glyph (B7) and a missing animation (B7) all end the session.
- **Direction:** check content at load (films, glyphs, animations, scenes), and degrade at run
  time: skip a film, play silence, drop an event.

### D7. Smaller design issues
- **Two definitions of Conrad.** Index 0 is used for protection, inventory, the `player_*`
  checks and the view. `kind == .player` is used for room following, hurt, `reveal` and
  `transport` (`presence.zig:50`, `world.zig:611,619,654`, `carriers.zig:207`). The city has
  three player-kind characters; it is harmless today but unguarded.
- **Near-duplicate helpers with silent differences:**
  - three "does this state wait for message X" scans (`world.zig:526 awaits`,
    `perception.zig:31 waitsFor`, `world.zig:625 listensForHits`);
  - three neighbour helpers, one of them unused (`grid.zig:138`);
  - about eight tier formulas (`grid.bandOf`, `world.zig:519`, `contacts.zig:59`, five in
    `perception.zig`, two in `carriers.zig`).

  Nothing tells deliberate quirks from accidents. Name each variant once in `grid.zig`, with
  tests that pin how they differ.
- **Films have two clocks.** Production always calls
  `playback.advance(view, playback.next_tick)` (`vector_player.zig:136`), so `Playback`'s tick
  timing (`vector_film.zig:139-165`) never decides anything, and its "late playback" test covers
  an unused path.
- **The build configures SDL for every target.** `linkSdl` runs at configure time
  (`build.zig:105-108`) and exits without pkg-config. `zig build agent` therefore fails on a
  machine without pkg-config, although the agent never links SDL.
- **The engine allocates during an update.** `contacts.register` takes an allocator only for
  wake-on-contact partners, which makes `World.update` fallible on out-of-memory in the middle of
  a walk. A fixed buffer would remove that.

## 3. Readability and maintainability

### R1. Magic numbers with no named origin. Confirmed.
- **The timer constants** (1,193,182 Hz and 17,024 counts per tick) are spelled out in five
  places: `step_clock.zig:14-15`, `key_latch.zig:9`, `vector_player.zig:12-13`,
  `continue_game.zig:103-105` (which re-derives the tick by hand) and `score.zig:32`.
- **`step_clock.jungle`** is the cadence of every level (`level.zig:277`).
- **Raw character kinds:** `level_screen.zig:414,575-577,601,690`, `contact.zig:137-138,190`
  and `perception.zig:114` use 1, 3, 5, 9, 10, 11 and 0xff, although `vocabulary.Kind` names
  them. `vocabulary.zig:34` claims the named kinds are the ones the engine distinguishes.
  `lowByte` is written three times.
- **Engine values:** scene 6 for the view room 0xff (`world.zig:398`), protection 60
  (`world.zig:620`), and 0xff meaning both "carried" and "no neighbour".
- **File offsets:** the bare offsets of the PRF and INS files in `content/music.zig`, and
  `0x1bcc0` in both `floppy_interface.zig:132` and `world_messages.zig:102`.
- **Direction:** named constants, each with a one-line origin.

### R2. Behaviour tables only partly meet DESIGN 7's readability gate. Confirmed.
- **Names:** 56 of 4,555 states have names; links and numbers are mostly `link_0..3` and
  `number_0..3`.
- **Signs:** the terrain arguments have inconsistent signs (`terrain.zig:84-135`):
  - `ledge_*`, `floor_edge_*` and `grab_edge_ahead` negate their argument;
  - `wall_beyond_gap`, `wall_starts` and `wall_ends` keep the original's raw offset, where
    positive means backward.
- **Direction:** normalise the signs at extraction, and track the naming coverage.

### R3. Dead code. Confirmed by search.
- In the scenes: the `.unavailable` view and `notice` of `front_end.zig:27,68,323,446`,
  `menu.Menu.selectedAction`, `Player.interactive` and `Screen.writeRgba`.
- In `Game`: the `.retry` branch at `game.zig:516`, which is unreachable since the continue
  screen always has a suspended level.
- In the engine: `contacts.Registration` and `grid.Grid.neighbor`.
- Read but never used: `Character.placement` and `unused_parameters`.
- `character_art.Art.missing` is written and never read.

### R4. Tests: what is missing, and tests that don't test their name
- **`World.update` has no in-repo test.** Nothing here covers the five ordering rules,
  `skipToAwaitedRule`, room crossing, the wake filters, `send`'s filters, the defeat countdown or
  catch-up. The fidelity evidence lives in flashback-re and cannot be run here, against
  AGENTS.md's "builds and tests must stand alone". The scratch `behavior/t/order.zig` could seed
  such tests.
- **No scene-transition tests** in `game.zig` (defeat, continue, retry or abandon, level to
  level, ending, demo cycling). There is nothing at all for `level_screen.zig`, `ending.zig`,
  `story.zig` or the password entry.
- **No positive test for interactive film pages**, which is where B1 lives.
- **Tests that don't check what they say:**
  - the `art_bank` raw-bank test asserts the encoding suspected wrong in B14;
  - the `string_table` "aliases" test never reads the aliased index;
  - `agent/startup_test.zig:6`, "Start hands over to the level", only checks a flag.
- **No differential test for the YM2612 fast path.** Nothing compares `runPlain` with
  `runChannel`. A scratch differential test (`audio/`) found them identical over about 4 million
  samples of random writes; it is worth committing.
- **The OPL reference test** reads files relative to the working directory, and the generator of
  its data lives in vpoolz.

### R5. Style
- The project's rule against inline imports (see `readable-zig-style`) is broken by
  `@import("std")` inside `vocabulary.zig:200` and `behavior/root.zig:12`.
- `presence.zig` puts its imports at the end of the file, and `effects.zig:8-10` puts a `pub`
  declaration between imports.
- The alias `music` names three different modules (`content/music.zig:5`, `soundtrack.zig:7-8`).
- `paused` at `game.zig:555` holds the film's whole duration.

## 4. Performance

No hot spot matters at today's sizes. The findings, most significant first:

### P1. The documented build is Debug. Confirmed.
README's `zig build` gives a Debug executable, as does the standalone recipe. In Debug, compared
with ReleaseFast:

| Measurement | Debug | ReleaseFast |
|---|---|---|
| Level load | 230–360 ms | 18–20 ms |
| `palette.writeRgba`, per frame | 812 µs | 80 µs |
| Densest music cue, share of real time | 2.8% | 0.47% |

Document `-Doptimize=ReleaseSafe`, which keeps the safety checks, or set a preferred optimize
mode in `build.zig`.

### P2. Audio latency (confirmed by calculation)
An effect is heard after the 50 ms queue lead plus up to 23 ms of SDL's 1,024-frame period. The
original takes about 12 ms. Two notes:
- The trade-off is documented only in flashback-re.
- The queue is topped up only from the update loop. A present that blocks for more than 50 ms
  (an occluded window, a slow compositor) would underrun. Suspected, not measured.

A 512-frame period would allow a shorter lead.

### P3. Minor waste (confirmed by measurement or reading)
- **Per frame:**
  - `palette.writeRgba` converts the whole frame (a 256-entry u32 lookup table would cut it);
  - `level.zig:689` copies the 57 KB picture even when nothing is drawn over it.
- **Per level load:**
  - `level_pack` reads `GLOBAL.ICN` twice, decodes the font twice and decodes the first room
    twice;
  - `Artwork.foreground` is a `[]bool` per pixel: 57 KB a room, about 3.6 MB a level.
- **Repeated unpacking:** the executable is unpacked again at 8 call sites, about 1 ms each,
  twice for each password check.
- **In the ending:** `ending.zig:194,245` uses a 229 KB stack buffer and converts a full RGBA
  frame that is then thrown away.
- **Input queues:** they pop with `orderedRemove(0)`, which is O(n) for each event.

## 6. Not reviewed, or reviewed only partly

- **Windows runtime.** There was no machine. B2's channel finding is proven from SDL 2.32.10's
  source, not run.
- **Real SDL audio and video drivers.** Only the dummy drivers were available, so vsync
  blocking, PulseAudio, PipeWire and ALSA behaviour were not observed, and the SDL 2.30
  signal-stack fix (721f366) was checked only by TLS size.
- **Fidelity of the "as the original does" claims.** The captures and research are in
  flashback-re. Third-party reimplementations are off limits. Where a finding depends on fidelity
  (B5, B14 Retry, D7), it says so.
- **Line-by-line equivalence of opl.zig with DOSBox, and of ym2612.zig with ymfm.** No upstream
  source was available. The in-repository oracle test and the scratch differential test were
  used instead.
- **Play routes not taken.** B1 was reproduced with only Conrad's start position moved, not by
  walking to a terminal. The ending was played through the title's code path only. Two of the
  three demos were not run.
- **`src/atlas/`**, which is untracked and in progress.
